# AGENTS.md — Boleia (Angola)

## Project

- Expo SDK 57 + React Native 0.86.3 + React 19.2.3 + TypeScript ~6.0.3
- App name: `boleia` (mobilidade partilhada interprovincial)
- New architecture ativada (default no SDK 57 — o campo `newArchEnabled` foi removido do schema do app.json)
- Single-package app (not a monorepo)

## Architecture

- **Entry point**: `index.ts` → `App.tsx` → `RootNavigator` (`src/navigation/RootNavigator.tsx`)
- **Routing**: React Navigation native-stack, three-level hierarchy:
    - `RootNavigator` → `SplashScreen` → `OnboardingScreen` → `BoleiaAuthNavigator` → `BoleiaMainNavigator`
    - `BoleiaAuthNavigator`: `Login` → `Register`/`ForgotPassword` → `OtpVerify` (OTP «signup» ou «reset», enviado por WhatsApp via backend) → `ResetPassword` → `ProfileSetup`
    - `BoleiaMainNavigator`: tabs (`PassengerTabs` / `DriverTabs`) + stack `Kyc`, `Vehicle`, `PublishTrip`, `RideDetail`, `PublicProfile`, `ActiveRide`, `Review`, `SosCenter`, `Notifications`
- **Styling**: NativeWind (Tailwind CSS for RN). Import `'./global.css'` in `App.tsx`. Metro config wired via `withNativeWind()`.
- **Design system**: modelo semântico Pixar/BlaBlaCar. Tokens em `src/store/colors.ts` (cores), `src/store/type.ts` (escala), `tailwind.config.js` (classes). Regra de emparelhamento obrigatória: `text` só sobre surfaces normais; sobre `primary`/`success`/`laterite`/`caution` usa-se sempre o token `on*` correspondente (`onPrimary`, `onSuccess`, `onWarning`, `cautionText`) — nunca `text` ou branco hardcoded. Validar com `node scripts/contrast.js`.
- **Cores**: `background` #F5F7FB, `card` #FFFFFF, `text` #001536, `secondary` #576680, `primary` #0071EB, `laterite` #B84412, `success` #107046, `caution` #FFCC56, `error` #BA303B (tema escuro tem variantes próprias). O alias legado `mato` foi removido — usar sempre `success`.
- **`laterite` é exclusivamente warning/bg/strong**: nunca como cor de texto, acento ou avatar. Rótulo/meta vai a `secondary`, acção/estado activo a `primary`, rail de rota origem=`text`/destino=`primary`, anel de avatar a `border`+`accentWeak`. Os únicos usos legítimos são bandas de estado (`band={themeColors.laterite}`), `ActivityIndicator` e o `tone="warning"` real.
- **Tipografia**: uma só família, **Hanken Grotesk** 400/500/700/800 (`font-sans`, `sansMedium`, `sansBold`, `sansExtraBold`). Sem monoespaçada, sem `font-display`, sem `uppercase`/`tracking` em labels. Escala: `titlePrimary` 28/31, `titleSecondary` 22/24, `titleTertiary` 18/20, `label` 16/18, `labelSmall` 14/16, `body` 16/19, `bodySmall` 14/17, `bodyXSmall` 12/17, `numberLarge` 40/44. Wordmark do Splash é a única excepção de tamanho (`text-[56px]`).
- **Sem gramática de bilhete**: `TicketCard`, `Perforation`, `Eyebrow`, `QRStamp` e `HistoryReceipt` foram eliminados. Superfícies neutras via `Card`; títulos via `SectionTitle`; rótulos via `GroupLabel`; banda de estado via `StatusStamp` (sempre com rótulo, nunca só cor).
- **Botão de voltar**: usar sempre o componente partilhado `src/components/BackButton.tsx` (`<BackButton onPress={...} />`). Não duplicar o `Pressable` com `chevron-back`.
- **Cabeçalho da app**: `src/components/AppHeader.tsx` (marca → casa, avatar → perfil). Vai nas **raízes de tab** — `HomeScreen`, `ExploreScreen`, `BookingsScreen`, `PublishScreen`, `TripsScreen` — e **não** no `ProfileScreen` (o avatar a levar ao perfil onde já se está é um clique morto) nem nos ecrãs empilhados, que já têm `BackButton` + título. **É barra fixa, fora do `ScrollView`** (fundo `card` + hairline `border`, `px-5` próprio) — um cabeçalho que scrolla com o conteúdo não é um cabeçalho. Mas **não é chrome do `native-stack`**: há nove botões de voltar escritos à mão nos ecrãs empilhados e um header nativo duplicaria todos eles. Deriva as rotas do papel (`currentRole`) em vez de receber props. Consequência da barra fixa: nos ecrãs com header, o `px-5` vive num `<View className="flex-1 px-5">` a seguir ao `AppHeader`, não no `SafeAreaView` (senão o header herda o padding duas vezes).
- **O header toca nas bordas**: os cinco ecrãs com header declaram `edges={['left', 'right', 'bottom']}` no `SafeAreaView` — **sem `top`**. O `AppHeader` lê `useSafeAreaInsets()` e aplica `paddingTop: insets.top + 12`, por isso é a **cor dele** (`card`) que preenche a faixa da barra de notificação até ao canto do ecrã. Com `top` incluído, essa faixa mostrava a cor do ecrã (`background`) a emendar com o branco do header a meio, e no iPhone com notch aparecia um rectângulo de cor errada ao lado da câmara. Os ecrãs **empilhados** (com `BackButton`) mantêm a edge de topo, porque aí não há header. No Android 15+ a barra é transparente por lei: desenhar por baixo com a cor certa _é_ o mecanismo — não há `backgroundColor` para lhe pôr.
- **Marca no header**: `assets/images/lockup.png` (374×280). É o `logo.png` **cortado a y=280**, o que remove a tagline "Disponibilidade, Rapidez e Segurança" e mantém o glifo + "BOLEIA". O corte foi medido, não escolhido a olho: a wordmark acaba em y≈275 e a tagline vive em y≈288-294 — a 42px de altura seriam menos de dois pixels, ou seja uma linha de ruído. **A placa escura `#121212` fica**: a wordmark é branca, e sem placa era branco sobre o `card` branco. O `mark.png` (150×150, só o glifo, cantos transparentes) já não é usado no header. **Nenhuma das imagens está na paleta** — o glifo é amarelo `#EEC619` e não existe token para ele; não tentar aproximá-lo com `caution`.
- **Sem scrollbar**: todo o `ScrollView` leva `showsVerticalScrollIndicator={false}` (ou `showsHorizontalScrollIndicator` nos horizontais). No Android o React Native mostra a barra por omissão e isso foi pedido explicitamente. Ao editarem um `ScrollView` a propriedade nova tem de entrar **antes** do `>` ou do `/>` — cuidado com o sedutor regex que transforma `<ScrollView …>` com filhos em auto-fechado e parte o ecrã.
- **Avatar**: usar sempre `src/components/Avatar.tsx` (36 / 44 / 64). Substituiu quatro versões escritas à mão que divergiam em tamanho e cor; uma delas punha `text` sobre `primary` e dava 3.9:1. **Não há fotografia de utilizador na app** — o campo `image` existe no esquema mas nunca é preenchido, porque o registo é telefone-primeiro sem upload. O componente aceita `image` na mesma, para quando existir. `initials()` **não inventa** a parte em falta: sem apelido dá uma inicial só, e sem nome nenhum o `Avatar` desenha um glifo de pessoa. **Nunca devolver `'?'`** — o registo aceita nome e apelido vazios, e um ponto de interrogação no avatar é um erro do sistema numa superfície que ninguém lê como mensagem de erro.
- **Selector segmentado**: `src/components/SegmentedControl.tsx` para qualquer escolha entre 2-4 opções (tema, papel de uso, tipo de verificação). Não escrever outro à mão.
- **Pesquisa = modo, e o modo muda o que se filtra.** Os dois modos usam o mesmo `GET /api/rides`, mas com vocabulários diferentes:
    - **Intermunicipal** manda `origin`/`destination` (códigos de município, `huambo.catabola`) e a província só **restringe o universo de escolha** (`restrictToProvince` no `LocalityPicker`). Sem essa restrição o rótulo era uma promessa que a pesquisa não cumpria: aceitaria Luanda → Benguela e devolveria a viagem como se fossem vizinhas.
    - **Interprovincial** manda `originProvinceId`/`destinationProvinceId` (códigos de província, `cuanza-norte`) e não escolhe município nenhum — é o `ProvincePicker` (`src/components/ProvincePicker.tsx`), com as 21 províncias e **sem caixa de pesquisa** (21 itens cabem e a pesquisa seria um campo a mais).
      No backend os dois pares são predicados **independentes** sobre a mesma paragem (`EXISTS` + `JOIN locality`), por isso mandar os dois pede a intersecção. Cada modo manda só o seu. **Nunca enviar um código de província em `origin`**: o backend procura esse valor no espaço dos municípios, e um slug de província não lá existe.
- **Trocar de modo limpa as quatro escolhas** (`from`/`to` e `fromProvince`/`toProvince`). São estado separado de propósito: um código de província e um de município vivem em espaços diferentes, e partilhar o campo obrigaria a lembrar a cada linha qual dos dois está lá.
- **Províncias e municípios são locais**: `src/lib/locations.ts` é gerado por `back/scripts/generate-locations.ts` a partir da seed, e é a única fonte nos clientes — não há `useLocalities` nem pedido para preencher um picker. O identificador é o código estático: província = slug (`luanda`), município = `provincia.municipio` (`bie.catabola`, `huambo.catabola`). O prefixo existe porque há três nomes repetidos no país (`Catabola`, `Canacassala`, `Quizenga`). As listas de províncias são chips em `flex-wrap`, lado a lado, nunca uma linha com scroll horizontal nem uma coluna.
- **Conta e segurança**: `src/screens/boleia/AccountScreen.tsx`, rota `Account`, aberto a partir do Perfil. Seis blocos num scroll (identidade, email, Google, sessões, palavra-passe, eliminar), **não seis ecrãs**. **Não precisa de backend novo** — cada bloco é um endpoint que já existia: `PATCH /api/account/profile`, `POST /api/account/delete`, `POST /api/account/unlink-google`, e os stock do better-auth `change-email`, `send-verification-email`, `list-sessions`, `revoke-session`, `revoke-other-sessions`, `change-password`, `link-social`. As sessões e as contas ligadas vão pelo **`authClient`**, não pelo axios: são endpoints do better-auth e é o `authClient` que tem a sessão.
- **Ligar o Google ≠ entrar com Google.** O botão de Google no ecrã de login **cria conta nova** e nunca liga a uma conta de telefone existente — o backend tem `disableImplicitLinking: true` (`back/src/auth/auth.ts:122`) de propósito, e mexer nisso reabriria a tomada de conta descrita no comentário aí. Ligar a uma conta que já existe só é possível **com sessão activa**, via `linkSocial`.
- **Email sintético**: toda a conta de telefone nasce com `<phone>@boleia.ao` porque o better-auth exige email (`phone-auth.ts:299`). Esse endereço não recebe correio e está sempre por verificar — a UI diz isso em vez de mostrar um "verificado" falso. E `requireEmailVerification: false` significa que a troca de email **aplica-se logo**: o endereço só vale depois do clique no link. Daí o aviso explícito no bloco do email.
- **`SessionRow`, nunca `Session`/`ApiSession`.** Já existem tipos com esses nomes para a _sessão do utilizador_. Interfaces em TypeScript **fundem-se** em vez de se substituírem: declarar `ApiSession` duas vezes não dá erro, dá uma personagem com os dois conjuntos de campos. Foi o que apanhou o primeiro rascunho do `AccountScreen`.
- **User-agent**: `src/lib/device.ts` reduz o `userAgent` a "Chrome · Windows". **Só traduz o que reconhece** — um agente desconhecido devolve `null` e mostra-se o que vier. A ordem importa: `crios`/`fxios` antes de `chrome`/`firefox`, senão um iPhone aparece como Chrome. As datas são escritas à mão, nunca `toLocaleDateString` (o Hermes sem ICU completo devolve inglês).
- **Composição, não casca**: cada secção de um ecrã tem a sua própria forma. Repetir "título + cartão com sombra" oito vezes seguidas, ou repetir a mesma banda tingida em cinco cartões, é o que faz uma interface parecer montada. O que une as secções é o peso tipográfico, não o invólucro. No `KycScreen` os grupos são **Identidade / Rosto / Condução** (por documento), não cinco secções com a mesma casca.
- **Progresso visível**: qualquer formulário longo diz quanto falta e o quê. `ProgressRail` (exportada de `PhotoSlot.tsx`) conta; a lista do que está em falta diz os nomes. Um botão cinzento sem explicação é um ecrã que não comunica.
- **Alvos de toque**: mínimo 44×44 (`MIN_TAP` em `src/store/type.ts`). Em controlos circulares menores, alargar com `hitSlop` em vez de inchar a métrica visual — calcular por `ceil((44 - px) / 2)` e confirmar que a folga entre vizinhos (ex.: ticks do relógio, `2·R·sin(π/n)`) continua maior que `2·hitSlop`.
- **State management**: Zustand para estado local. **Todos** os dados vêm da API real (`src/lib/api.ts`, axios) contra o backend NestJS (`API_URL` via react-native-dotenv). Não existe camada mock.
- **Tempo real**: WebSocket `socket.io` no namespace `/trips` (`src/lib/socket.ts`). Autenticação por `handshake.auth.token` — o gateway **só** aceita Bearer e não olha para cookies, daí vir o valor do cookie (ver `auth-cookie.ts`). Salas `ride:<id>`; eventos `ride:snapshot`, `ride:started`, `ride:progress`, `ride:finished`, `ride:cancelled`, `booking:created`, `booking:decided`, `booking:cancelled`. As chaves têm de coincidir com `RideEvent` em `back/src/rides/ride-events.ts`.
- **Push**: Expo Push Service. `src/hooks/usePushRegistration.ts` regista o token em `POST /api/push/devices` quando há sessão e a permissão já foi concedida; a permissão é pedida no ecrã de notificações, nunca ao arrancar. O backend invalida tokens com `DeviceNotRegistered`.
- **Fonte tree**: `src/{components,hooks,lib,navigation,screens,store,types,utils}`. Cliente HTTP em `src/lib/api.ts`; adaptadores de domínio em `src/lib/rideMapper.ts` (`toRide`, `toBooking`, `rideProgressFraction`); formatadores puros em `src/lib/format.ts`; províncias e municípios em `src/lib/locations.ts` (gerado, sem rede). React Query para toda a leitura remota.
- **Ecrãs sem backend**: `ReviewScreen`, `SosCenterScreen` e `PublicProfileScreen` mantêm-se na navegação e dizem explicitamente que a funcionalidade ainda não existe. Não inventar notas, avaliações, alertas SOS nem perfis: sem endpoint, a app não mostra o dado.
- **Pagamentos**: a v1 só usa `dinheiro` (CASH). `WALLET` e `MULTICAIXA` existem no esquema do backend mas sem carteira nem integração Multicaixa, por isso não são oferecidos na UI. `PaymentKind` mapeia `CASH → 'dinheiro'` em `rideMapper.ts`.
- **Source tree**: `src/{components,hooks,lib,navigation,screens,store,types,utils}`. Cliente HTTP em `src/lib/api.ts`; elegibilidade real em `src/lib/eligibility.ts` (gates de pedir/registar corrida). Não reintroduzir `src/mock/`.
- **KYC obrigatório (real), só documentos**: passageiro precisa `kycPassenger=VERIFIED` (BI frente/verso + ≥2 selfies + corpo inteiro) para pedir; motorista precisa `kycDriver=VERIFIED` (BI + selfie + carta) + ≥1 viatura `VERIFIED` para publicar (`KycScreen` tem modo passageiro/motorista, upload real via Cloudinary). **Não há campos de texto**: nada de nome, número de BI, número de carta ou validade — o revisor lê-os na fotografia, e o pedido identifica-se pelo nome da conta. Os gates são validados também no servidor.

## Quirks & gotchas

- **`/android` and `/ios` are gitignored**: this is a prebuild / CNG workflow. Run `npx expo prebuild` to regenerate native directories. Do NOT commit native folders.
- **Expo Updates** configured with OTA URL e política `appVersion`. `eas.json` com perfis `development`/`preview`/`production`; `APP_ENV` decide que ficheiro `.env.*` o `react-native-dotenv` carrega (a biblioteca já resolve `.env` < `.env.local` < `.env.<APP_ENV>` < `.env.<APP_ENV>.local`).
- **Identidade**: `android.package` e `ios.bundleIdentifier` são `ao.boleia.app`. Alterá-los depois de publicar na Play Store/App Store cria uma app nova, não uma actualização.
- **No test framework** is configured. If adding tests, use Jest + React Native Testing Library (the `@react-native` ESLint config assumes this convention).
- **Auth (API real)**: phone-first — sign-up exige OTP obrigatório entregue por WhatsApp (backend), senha mín. 8. A sessão vive num **cookie** gerido pelo cliente oficial do better-auth (`src/lib/auth-client.ts`, plugin `@better-auth/expo` com SecureStore) — não há token guardado pela app, nem chave `boleia.authToken`. Login/registo/OTP/reset vão por `src/lib/phone-auth.ts` (`$fetch` do `authClient`, porque `/phone/*` vem de um plugin do backend e não tem métodos gerados); o resto da API continua em axios (`src/lib/api.ts`). `useSessionUserId()` e `useSessionUser()` leem do `authClient.useSession()` e devolvem `null`/`null` sem sessão — nunca um id de recurso. O `appStore` guarda apenas `currentRole` e `onboardingSeen`; `resetAfterLogout()` repõe o papel ao sair. 401 → `authClient.signOut()` + reset de navegação + `queryClient.clear()`.
- **O valor do cookie é também o Bearer do WebSocket**: `src/lib/auth-cookie.ts` extrai `better-auth.session_token` de `await authClient.getCookie()` (assíncrono desde a 1.7) e dá-o tanto ao header `Cookie` do axios como ao `handshake.auth.token` do gateway. É a única fonte; **não** criar uma segunda chave no SecureStore. Atira em vez de devolver `undefined`, porque um token em falta falha em silêncio no socket.
- **`GET /api/rides` devolve o array puro e o total em `X-Total-Count`.** O CORS do backend expõe esse cabeçalho; se for retirado, a app perde a contagem de resultados.
- **Fuso**: o backend interpretou e devolve as horas de paragem em WAT (UTC+1). Não recalcular nem converter para UTC no cliente.
- **Troca de papel** (passageiro ↔ motorista) só no ecrã de Perfil ("Modo de uso").
- **Homepage**: sem publicidade. `TripSearch` (intermunicipal/interprovincial, origem/destino, dia) com resultados inline e pesquisas recentes (`src/lib/recentSearches.ts`, AsyncStorage, máx. 5, só local).
- **Publicar viagem**: wizard de **3 passos** (Rota e dia → Preço e viatura → Rever) em `PublishTripScreen`. Publica só pela API; não existe espelho local.
- **No `.env` files** committed, excepto `.env.example` e `.env.production.example`. Use `.env` + `.env.local` (gitignored) for secrets. Produção tem de ser HTTPS.
